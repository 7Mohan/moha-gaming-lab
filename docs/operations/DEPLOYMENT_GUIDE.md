# Moha Gaming Lab — Production Deployment & Launch Guide

This guide provides an end-to-end walkthrough for taking Moha Gaming Lab from code repository into a fully operational, hardened production environment.

---

## 1. Production Architecture Overview

```text
       [End Users & Mobile Devices]
                    │
                    ▼
          [Cloudflare Edge / CDN]
     (DDoS Mitigation, SSL/TLS, Caching)
                    │
                    ▼
          [Next.js 15 App Router]
    (Vercel Edge/Serverless OR Docker Node 20)
     ├── Static HTML & AVIF/WebP Images (Cached at Edge)
     ├── Dynamic Pages & Server Actions
     ├── Middleware (Auth Gate, Maintenance Mode, CSP)
     └── REST / API Routes (/api/health, /api/download/*)
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
 [Supabase Managed BaaS]   [External Services]
  ├── PostgreSQL 15 + RLS   ├── Brevo (Transactional Email)
  ├── PgBouncer Pooler      ├── Google Analytics 4
  ├── Supabase Auth         └── Google AdSense
  └── Private S3 Storage (APKs)
```

---

## 2. Infrastructure Prerequisites

Before initiating production deployment, ensure you have:
1. **Registered Domain:** e.g., `mohagaminglab.com`
2. **Supabase Production Project:** Managed PostgreSQL, Auth, and Storage instance.
3. **Hosting Account:** Vercel (Recommended) or Linux VPS with Docker & Docker Compose.
4. **Transactional Email:** Brevo (formerly Sendinblue) account with verified sender domain.
5. **DNS/CDN Management:** Cloudflare DNS for DDoS protection and edge caching.

## 3. Database & Storage Initialization

### 1. Apply Supabase Migrations
Connect to the production database via Supabase Dashboard SQL Editor or Prisma CLI:
```bash
# Set your direct connection string
export DATABASE_URL="postgresql://postgres:[PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres?sslmode=require"

# Deploy all schema migrations
npx prisma migrate deploy

# Verify schema state
npx prisma migrate status
```

### 2. Apply Storage & RLS Policies
Ensure `supabase/migrations/20260910_phase12_download_storage.sql` has been executed in the Supabase SQL Editor:
- Creates private `app-releases` bucket.
- Establishes RLS policies restricting file uploads exclusively to authenticated SuperAdmins.
- Enforces read access via signed URLs generated by the application gateway.

## 5. Hosting Option B: Self-Hosted Docker Deployment

1. **Provision Linux Server:** Ubuntu 22.04 LTS / 24.04 LTS with Docker 26+ and Docker Compose v2.
2. **Clone Repository & Setup Environment:**
   ```bash
   git clone <REPO_URL> moha-gaming-lab
   cd moha-gaming-lab
   cp .env.production.example .env.production
   # Edit .env.production with your real production secrets
   nano .env.production
   ```
3. **Launch Container Stack:**
   ```bash
   docker compose up --build -d
   ```
4. **Configure Reverse Proxy (Nginx / Caddy):**
   Point your reverse proxy to `http://127.0.0.1:3000` with HTTP/2 and automated Let's Encrypt SSL certificates.

## 6. DNS & Cloudflare Configuration

1. In Cloudflare DNS management, add:
   - **Type:** `CNAME` | **Name:** `@` (or `www`) | **Target:** `cname.vercel-dns.com` | **Proxy status:** Proxied (Orange Cloud)
2. **SSL/TLS Settings:**
   - Encryption mode: **Full (strict)**.
   - Enable **Always Use HTTPS**.
   - Minimum TLS Version: **TLS 1.2**.
3. **Speed & Caching Rules:**
   - Enable **Brotli** and **HTTP/3 (with QUIC)**.
   - Set Edge Cache TTL: Respect Existing Headers (`s-maxage` from Next.js).
   - Under WebSockets: Ensure **WebSockets** is toggled ON (required for Supabase Realtime).

## 7. Pre-Flight Launch Verification Checklist

- [ ] `GET /api/health` returns HTTP 200 with `{ status: "ok" }`
- [ ] `GET /api/health/ready` returns HTTP 200 with `{ status: "ready" }`
- [ ] `GET /robots.txt` returns HTTP 200 and points to `https://mohagaminglab.com/sitemap.xml`
- [ ] `GET /sitemap.xml` returns HTTP 200 with valid XML URLs
- [ ] Security headers check: CSP, HSTS, X-Frame-Options, X-Content-Type-Options present
- [ ] Authentication check: SuperAdmin can log in at `/admin/login`
- [ ] Download check: APK signed URL resolves and starts file transfer
- [ ] Mobile check: Viewport meta tag and responsive UI verified
- [ ] Monitoring check: External uptime probe configured and healthy
